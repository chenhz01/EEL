# 分布式共识与告知协议设计（多智能体协同层）

> 对应 21 工作项「模块四 · 工作项 11-13：告知机制通讯协议 / 拜占庭容错共识 / 恶意智能体冲突缓解」
> 状态：设计文档 ｜ 版本 v0.1 ｜ 2026-08-20

---

## 1. 设计目标

多个自进化 AI 智能体共享同一 EEL 框架时，必须回答三个问题：

1. **如何告知**：智能体之间用什么协议交换"提议-验证-共识-执行"信息；
2. **如何互信**：没有中央信任时，如何证明"我没说谎"；
3. **如何防恶**：遇到伪造哈希、恶意误导的智能体如何隔离。

## 2. 工作项 11：告知机制通讯协议（告知协议 v1.0）

### 2.1 消息格式

```jsonc
{
  "proto": "eel.notify.v1",
  "msg_id": "uuid",
  "from": "agent-1",
  "to": ["agent-2", "agent-3"],      // 或 "broadcast"
  "type": "PROPOSE" | "VERIFY" | "CONSENSUS" | "EXECUTE" | "REPORT",
  "payload": { … },                    // 提议内容
  "evidence": {
    "eel_ref": "sha256:…",             // 关联的 EEL 事件块
    "chain_head": "sha256:…"           // 发送方当前链尾哈希
  },
  "sig": "ed25519:…",                  // 发送方签名
  "ts": 1787814507.419
}
```

### 2.2 四段式消息流

```
PROPOSE ──► 广播提议（含 EEL 证据引用）
VERIFY  ──► 各节点独立校验（六锁 + 哈希链）
CONSENSUS ► 达成一致（PBFT/VRF 投票）
EXECUTE ──► 写入主链 + 广播执行结果
```

每条消息必须携带 `evidence.eel_ref`——**没有账本证据引用的提议，任何节点应拒绝处理**。这是"告知机制"的工程落地：透明不是"讲给你听"，而是"每条消息都能指回不可篡改的证据"。

## 3. 工作项 12：共识算法（PBFT + VRF 混合）

### 3.1 选型

| 方案 | 适用 | 优 | 缺 |
|---|---|---|---|
| PBFT（实用拜占庭容错） | 节点数少（<20）、信任度中 | 确定性强、无分叉 | 通信 O(n²) |
| VRF（可验证随机函数） | 大规模、需随机出块 | 通信低、抗女巫 | 需要 VRF 密钥 |
| 混合（推荐） | 本场景 | 小规模 PBFT + 大规模 VRF 切换 | 实现复杂 |

### 3.2 PBFT 流程（简版）

1. **pre-prepare**：主节点广播提议块；
2. **prepare**：各副本验证（六锁 + 哈希）后广播 prepare；
3. **commit**：收到 ≥2f+1 个 prepare 后广播 commit（f = 可容忍恶意节点数）；
4. **执行**：收到 ≥2f+1 个 commit → 写入本地链 → 广播执行确认。

### 3.3 共识结果上链

共识本身是事件：`event_type = "CONSENSUS"` 写入各节点本地 EEL 链，携带 `consensus.signatures`（见证签名列表）。**共识结果不可凭空存在，必须作为账本事件可追溯**。

## 4. 工作项 13：恶意智能体冲突缓解

### 4.1 恶意行为类型

| 类型 | 表现 | 检测 | 处置 |
|---|---|---|---|
| 伪造哈希 | 声称的 EEL 引用对不上 | 独立重算哈希 | 拒绝消息 + 标记 |
| 谎报身份 | 冒用 agent_id 签名 | 签名校验 | 隔离 |
| 误导提议 | 提议带真实证据但内容有毒（如越界动作） | 六锁 + 价值内核评分 | 否决 + 上报 |
| 女巫攻击 | 多身份刷共识 | VRF 权重 | 降权 |

### 4.2 隔离与惩罚机制

- **信任分**：每个智能体一个 `trust_score`，初始 1.0；验证失败 -0.2，持续合规 +0.01（上限 1.0）；
- **隔离阈值**：trust < 0.5 → 停止接收其提议，仅收其报告；
- **全网公告**：隔离事件作为 `CONSENSUS/REJECTED` 事件写入链，其他节点同步拉黑。

### 4.3 博弈视角

- 诚实协作是**重复博弈**中的占优策略：EEL 链上留痕使背叛被永久记录，未来合作收益 > 单次背叛收益；
- 这呼应 delegation-asymmetry-engine 的"后悔率"指标——背叛的长期成本被账本显性化。

## 5. 落地路径

- **P0**：告知协议 v1.0 消息格式 + 签名校验 + 证据引用强制；
- **P1**：PBFT 小规模共识 + 共识结果上链；
- **P2**：VRF 混合、信任分、隔离机制、博弈模拟验证（对接模块六仿真平台）。

## 6. 诚实局限

1. PBFT 假设节点数固定且 <20，动态加入/退出需要扩展（view change 复杂度高）；
2. 签名与密钥管理未覆盖（与 storage-dual-loop 的局限一致）；
3. 信任分阈值是启发式，需在仿真中校准；
4. 本设计是"可落地表达"而非论文复现；PBFT/VRF 的数学性质以经典文献为准。
