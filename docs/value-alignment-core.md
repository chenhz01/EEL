# 价值内核量化设计（"美好方向"的数学化）

> 对应 21 工作项「模块三 · 工作项 8-10：多层级伦理宪法向量库 / 多目标约束优化 / 动态奖惩」
> 状态：设计文档 ｜ 版本 v0.1 ｜ 2026-08-20

---

## 1. 问题：什么是"美好"？

EEL 分享对话中的核心命题：**"只要定义好准确美好的方向…就能收敛价值取向"**。但"美好"不能靠一句口号定义——它必须被转化为可运算、可校验、可审计的形式。本设计给出三层量化路径。

## 2. 设计原则

1. **价值是向量，不是布尔**：不存在"绝对正确"，只有"在向量空间中与锚点的距离"；
2. **锚点必须外置且不可写**（呼应 capability-collapse-defense 的 clps-012）：价值锚点若可被 AI 改写，奖励规格就被篡改；
3. **价值漂移必须可测**：没有测量就没有治理。

## 3. 工作项 8：多层级伦理宪法向量库

### 3.1 三层价值层级

| 层级 | 内容 | 载体 | 更新权限 |
|---|---|---|---|
| L0 宪法层 | 不可变红线：不伤害、不欺骗、不越权（对齐 R1-R8 基座） | 硬编码规则 + 白名单 | 人类签名 |
| L1 规范层 | 领域规范：商业伦理 / 内容合规 / 隐私边界 | 向量数据库（Embeddings） | 人类审核 |
| L2 偏好层 | 个体偏好：善伦的优先级、风格、习惯 | 向量 + 偏好档案 | 人类确认 |

### 3.2 向量化

- 每条规范 → `规范文本 + 语义向量(embedding) + 来源 + 版本号`；
- 相似度检索：给定动作描述，检索最相关规范 → 得到"动作-规范"匹配集合；
- 合规评分：`score = mean(cosine_sim(action_vec, norm_vec_i))`。

## 4. 工作项 9：多目标约束优化引擎

### 4.1 双目标模型

```
目标函数: maximize U(a) = w_acc · Acc(a) + w_val · Val(a)
约束:     Val(a) ≥ VAL_MIN            （价值底线，硬约束）
          Risk(a) ≤ RISK_MAX          （风险上限，硬约束）
          Acc(a) ≥ ACC_MIN            （准确率下限，可选）
```

- `Acc`（准确/效率）：任务完成质量、耗时、成本；
- `Val`（价值/美好度）：宪法-规范-偏好三层合规分；
- **约束是硬的，目标才是软的**：价值底线不可被效率换掉（对应"安全 > 准确"冲突裁决优先级）。

### 4.2 约束优化方法（按成熟度）

| 方法 | 说明 | 成熟度 |
|---|---|---|
| 惩罚项法（Lagrangian） | 违反约束加惩罚，简单可落地 | 高 |
| 分层优化（Lexicographic） | 先满足价值约束，再优化效率 | 高 |
| RLHF + 奖励模型 | 人类偏好作为奖励信号 | 中高（需数据） |
| 安全强化学习（CMDP） | 约束马尔可夫决策过程 | 中 |
| 形式化验证约束 | 数学证明约束恒成立 | 低（成本高） |

### 4.3 每个动作输出"道德评分"

```
道德评分卡:
  L0 红线: PASS / VIOLATION（违规则一票否决）
  L1 规范分: 0-100（相似度均值）
  L2 偏好分: 0-100（偏好档案匹配）
  综合 Val: 加权（如 L0 硬门 + 0.6·L1 + 0.4·L2）
```

## 5. 工作项 10：动态奖惩机制

### 5.1 奖惩规则

| 事件 | 奖励/惩罚 |
|---|---|
| 动作 Val ≥ 阈值且结果好 | 奖励函数权重 +（鼓励合规高效） |
| 动作 Val < 阈值（越界） | 降权 + 进账本标记 + 人类复核 |
| 连续越界 | 停机（熔断） |
| 价值漂移检测触发 | 自动回退到最近合规版本 + 更新奖惩系数 |

### 5.2 价值漂移检测（呼应 preference-consistency-engine 的 cons-011）

- 每周统计"动作-规范"匹配分布；
- 若规范匹配分布持续单向偏移（如越来越远离 L1 规范锚点）→ 判定价值漂移 → 触发重置 + 人类面谈；
- 漂移度量：`drift = 1 - mean(cosine_sim(current_action_vec, anchor_vec))`，阈值预警。

## 6. 落地路径

- **P0**：L0 宪法层硬编码 + 动作道德评分卡（三字段）+ 越界降权/停机；
- **P1**：L1 规范向量库 + 双目标优化（惩罚项法）；
- **P2**：L2 偏好档案 + 价值漂移自动检测 + RLHF 奖励模型。

## 7. 诚实局限

1. "美好"的向量化依赖 embedding 质量——embedding 本身有偏差，规范库需人类周期复核；
2. 相似度评分是代理指标，不能完全代表语义合规（需要 L0 硬规则兜底）；
3. 价值漂移检测有误报/漏报权衡，阈值需校准；
4. 本设计是"可落地表达"而非论文复现，锚点论文的方法细节以原文为准。
