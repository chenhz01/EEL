# L4 复现实验设计：创新重组律（96.8% 定律）

> **目标**：复现 [arXiv:2608.17471](https://arxiv.org/abs/2608.17471) 的核心量化结论，把「96.8% 重组」从论文声称变成**本仓库实证数据**——L4 从候选定律升级为已验证定律的第一步。
>
> **状态**：设计 v1.0（2026-08-24）｜ 预计执行窗口：1-2 周 ｜ 优先级：P0（最快出成果线）

---

## 一、验证对象（3 个假设）

| # | 假设 | 论文声称值 | 验证标准 |
|---|------|-----------|---------|
| H1 | AI 设计落在人类设计空间内的比例 | ≈ 96.8% | 实测比例落在 [0.90, 0.99] 区间 |
| H2 | 精确复刻（精确匹配已有人类算法）比例 | ≈ 50% | 实测比例落在 [0.35, 0.65] |
| H3 | 真超车（超越人类 SOTA）比例 | ≈ 10/72 | 实测 ≥1 例且 <20% |

**证伪条件**：任一假设偏离区间超 3 个标准差 → 该部分定律不成立，回退为「论文复现失败」。

## 二、方法（映射论文原方法）

### 2.1 数据源（3 组独立）

| 组 | 来源 | 样本量 | 用途 |
|---|------|--------|------|
| A | Agent 生成的设计（论文原始设置） | ≥72 配置 | 复现论文核心数字 |
| B | **本仓库 Skill 目录**（正明孵化产线产出） | 现有 Skill 全量 | 验证定律在本系统的适用性 |
| C | 公开 Agent 框架设计（LangChain/AutoGen 等官方示例） | ≥50 配置 | 交叉验证泛化性 |

### 2.2 四模块拆解（对齐 innv-001 规格）

每个设计拆为：
1. **触发条件**（什么输入触发）
2. **处理流程**（步骤序列）
3. **输出格式**（产出结构）
4. **依赖组件**（使用的库/API）

### 2.3 设计空间映射（对齐 innv-002 规格）

- 从人类方法推导「任务专属算法设计空间」（论文方法）
- 把 A/B/C 三组设计映射进空间，量化落点：
  - 空间内 → 统计与已知设计的重合度（innv-004）
  - 重合度 >80% → 精确复刻/换壳（innv-005）
  - 空间外 → 潜在真超车候选

### 2.4 判定标准（对齐 innv-003 三选一）

```
复用：四模块中 ≥3 模块与已知设计重合 >80%
重组：模块重新组合但单模块无新意（重合 30%-80%）
新组合：模块差异 >30% 或跳出人类设计空间
```

## 三、实验流程（5 步，1-2 周）

| 步 | 动作 | 产出 | 耗时 |
|---|------|------|------|
| 1 | 搭建设计空间映射工具（Python，纯 stdlib 优先） | 映射脚本 | 2-3 天 |

| 5 | 汇总对比论文数字，写入实验结果报告 | 报告 + 更新 laws.md | 1 天 |

## 五、诚实边界（先读再评）

1. **四模块拆解粒度是主观的**——需先定拆解规范 + 测评分者一致性（innv-004 诚实局限）
2. **B 组样本量小**（正明 Skill 目录有限）——只作适用性验证，不作普适结论
3. **论文方法细节以原文为准**——若论文未公开完整映射方法，以「近似复现」标注
4. **真超车判定需要外部基准**——B 组 Skill 的绩效数据可能不完整，H3 主要靠 A/C 组

## 六、与 L2 的衔接（第二阶段）

- L4 的「设计空间映射」→ L2 的「能力曲线测量」方法同源
- 正明每日进化系统（真实自进化闭环）即 L2 实验场
