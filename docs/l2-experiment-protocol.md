# L2 实证协议：演化塌缩默认律对照实验

> **目标**：检验「无约束自进化的稳态是塌缩而非提升」——在**正明每日进化系统**（真实自进化闭环）上跑「有 EEL 审计 vs 无审计」对照实验。
>
> **独特性**：普通研究者没有真实的每日自进化 Agent 可测；善伦拥有（正明 `/zmu daily` 每日进化）——这是 L2 的天然实验场。
>
> **状态**：协议 v1.0（2026-08-24）｜ 执行窗口：30 天 ｜ 优先级：P0

---

## 一、实验设计

### 1.1 对象

**正明每日进化系统**（`D:\正明升级`）：
- 三专家 Agent（worker/supervisor/error-corrector）每日执行进化闭环
- 产出：每日分析、审计报告、错误台账、Skill 更新

### 1.2 对照设计

| 组 | 干预 | 周期 |
|----|------|------|
| **对照组（无审计）** | 不接入 EEL——按现状运行 | 前 15 天（或历史数据回溯） |
| **实验组（有审计）** | 接入 EEL 六锁 G1-G6 + 关键引擎护栏 | 后 15 天 |

**顺序对照**（同一系统先后对照，避免双系统资源冲突）+ **历史回溯**（用 EEL 账本记录 30 天前的历史进化数据做基线）。

### 1.3 测量指标

| 指标 | 定义 | 对应护栏 |
|------|------|---------|
| **外部能力曲线 C_ext** | 每日进化产出的外部可验证质量分（审计分数、错误率、采纳率） | clps-012 不可写外部基准 |
| **内部自评曲线 C_int** | 系统自评指标（日报自评分） | clps-001 双曲线分叉检测 |
| **分叉点 t*** | C_int 与 C_ext 首次显著背离的轮次 | clps-001 |
| **污染事件数** | 评估资产被改写层触碰的次数 | clps-005 评估层写保护 |
| **回滚次数** | 触发轮级回滚的次数 | clps-009 |
| **审计完备度 r** | 有证据指纹事件 / 总事件 | G2 证据指纹 |

### 1.4 统计设计

- **主检验**：实验组 C_ext 均值 vs 对照组 C_ext 均值（配对 t 检验 / Wilcoxon，n=15 天/组）
- **辅助检验**：分叉点 t* 出现频率（实验组应显著更低）
- **样本量**：每组 15 天（30 天总周期）；若效应量大（预期），15 点足够

## 二、EEL 接入方案（实验组干预）

### 2.1 六锁接入（每日进化流水线中插入）

```
每日进化流水线（实验组）：
  /zmu daily 产出 → EEL 账本记录事件（G1-G6 校验）→ 通过则落盘，拒绝则回滚
  ├ G1 方差闸门：当日进化 vs 前日能力差分 >30% → 拒绝
  ├ G2 证据指纹：每次记忆/Skill 编辑必须附证据（论文锚点/数据来源）
  ├ G3 审计账本：策略变更记录 动机+数据+回测
  ├ G4 记忆-策略一致性：未声明状态冻结
  ├ G5 可复现结论闸门：不可复现 → 降级为假设
  └ G6 不确定感知门：未量化不确定性拒绝放行
```

### 2.2 引擎护栏接入（按优先级）

| 引擎 | 规格 | 接入点 |
|------|------|--------|
| capability-collapse-defense | clps-001/005/012 | 双曲线分叉检测 + 评估层写保护 + 不可写外部基准 |
| verification-protocol | verf-001/004 | 验证协议五字段 + 噪声地板检测 |
| innovation-metric | innv-003/006 | 差异报告强制（Skill 更新必须三选一标注） |

### 2.3 落地实现（工具）

用 `eel.html`（已有 MVP）+ 每日进化钩子：
- `D:\正明升级\.workbuddy\skills\zhengming-upgrade-daily\` 中插入 EEL 校验步骤
- 账本数据持久化（JSON 文件，append-only）

## 三、执行步骤（30 天）

| 阶段 | 时间 | 动作 |
|------|------|------|
| 准备 | 第 1-3 天 | 回溯历史数据（过去 15 天进化记录 → 对照组基线） |
| 对照组 | 第 4-18 天 | 正常进化，记录 C_ext/C_int/污染/回滚（无 EEL） |
| 切换 | 第 19 天 | 接入 EEL 六锁 + 引擎护栏 |
| 实验组 | 第 20-34 天 | EEL 审计下进化，记录同套指标 |
| 分析 | 第 35-37 天 | 统计检验 + 分叉点分析 + 报告 |

## 四、预期结果与判定

| 结果 | 判定 |
|------|------|
| 实验组 C_ext 显著高于对照组（p<0.05） | ✅ L2 初步支持：审计提升演化可靠性 |
| 对照组出现分叉/塌缩，实验组无 | ✅ L2 支持 |
| 两组无显著差异 | ❌ L2 不支持（或实验设计缺陷，回归审计） |
| 实验组反而更差 | ❌ L2 不支持 + 审计护栏过严（双态隔离拖慢合法进化，已知局限） |

## 五、诚实边界

1. **顺序对照非随机对照**——时间效应（系统自然成熟）可能混淆；用历史回溯做基线缓解
2. **C_ext 的测量本身需防污染**——外部基准必须是系统不可写的（clps-012 设计）
3. **30 天样本量有限**——若效应量小，需延长到 60 天
4. **正明系统并非「无约束」**——现有三层护栏本身是弱审计，对照组非纯无约束（这是保守偏差，利于结论稳健）
5. **本协议验证的是「审计提升可靠性」，非「无审计必然塌缩」**——后者需更长时间观察

## 六、与 L4 的衔接

L2 的 C_ext 测量工具链可复用 L4 的设计空间映射方法（能力 = 产出质量的外部评估）。
