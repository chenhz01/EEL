## 问法层

### cons-001 多问法交叉评分（P0 · 2608.17644）

- **问题**：LLM 偏好是问法建构的——"值多少钱 / 省多少时间 / 相比 X 优先级如何"三种问法可给出互相矛盾的评分，单问法点估计掩盖不自洽
- **方案**：所有裂变产出与商机信号的价值评分至少跑三种问法，报告**中位数 + 方差**；方差代替点估计作为该评分的置信度
- **来源**：对比CN-w15-05 P0 + 论文CN-w03-02
- **集成**：Capsule-ZM-KG 卡片入库评分字段（value_median / value_var / value_frames）

### cons-002 重述稳定性检验（P1 · 2608.17644）

- **问题**：同一问题原样重问，LLM 可能给出不同答案；重述漂移是自洽性的最低门槛信号
- **方案**：对同类判断多次重述交叉验证，用重述间方差估计不确定性，喂给护栏做风险加权，方差大→只展示不替选
- **来源**：对比CN-w17-07 P1
- **集成**：三层护栏（偏好推断列为高风险动作）

## 检验层

### cons-003 效用函数拟合检验（P0 · 2608.17644）

- **问题**：论文证明同一批基数偏好判断无法被任何单一效用函数忠实概括——拟合出的效用函数是虚假一致性
- **方案**：对一组价值/偏好判断做效用函数拟合残差检验；残差超阈判定"不自洽集合"，禁止进入效用驱动的自动决策
- **来源**：论文CN-w03-02 核心实验
- **集成**：AI Commerce Hub 分级引擎前置校验

### cons-004 传递性检验（P0 · 2608.17644）

- **问题**：偏好不自洽的表现之一是传递性破坏：A>B 且 B>C 但 A<C；不检验传递性就无法发现集合级矛盾
- **方案**：对组内判断两两比较，检验传递性是否成立；破坏传递性的集合打"冲突标记"，降级为仅供参考
- **来源**：对比CN-w18-09 P0
- **集成**：六态状态机 published 前新增"集合级自洽性检查"关卡

### cons-005 无差异点检验（P1 · 2608.17644）

- **问题**：论文的检验口径——A、B 两物的支付意愿之差，不等于让此人对交换二者无差异所需的补偿金；无差异点矛盾是另一种不自洽
- **方案**：对基数判断做无差异点检验，发现显著矛盾即标记"价值待定"
- **来源**：论文CN-w03-02 实验设计
- **集成**：UUMit 定价建议校验

## 闸门层

### cons-006 集合级一致性关卡（P0 · 2608.17644 + 2608.17756）

- **问题**：状态机验证粒度是"条"，但"条条正确、整体失效"是常态——逐条放行无法发现集合级矛盾
- **方案**：在 published 之前增加**集合级一致性检查**作为并列关卡：多条判断共存时先跑一致性检验（传递性 + 无差异点），不自洽的集合整批降级为"仅供参考"，不进自动执行链路
- **来源**：对比CN-w18-09 融合点（诊断协议补第三环）
- **集成**：六态状态机 published 关卡 + EEL G2 证据环之后的第三环

### cons-007 区间报价代替点估计（P0 · 2608.17644）

- **问题**：定价建议用点估计自动执行，是把不自洽输入伪装成精确决策
- **方案**：UUMit 与 AI Commerce Hub 的定价建议采用"区间报价 + 人类确认"而非点估计自动执行，规避效用函数幻象
- **来源**：对比CN-w17-07 P2 + 对比CN-w19-02 P2
- **集成**：UUMit 订阅定价流程 + 商机日报V3

### cons-008 方差超阈值标记（P1 · 2608.17644）

- **问题**：多问法方差超阈的评分若仍按正常权重参与排序，会污染下游决策
- **方案**：方差超阈值的卡片标记"价值待定"，不进入高复用推荐池；评分以中位数 + 方差一起入库
- **来源**：对比CN-w15-05 融合点
- **集成**：Capsule-ZM-KG 推荐池过滤

### cons-009 商机分级证据类型必填（P1 · 2608.17644 + 2608.17744）

- **问题**：付费意愿若来自 LLM 推演，等于把决策建立在自相矛盾的输入上；且小样本验证的指标波动可能大于真实效应
- **方案**：商机分级引擎"付费意愿"字段必须标注证据来源——真实成交 / 真实试用 / LLM 推演三类；LLM 推演类不得单独支撑 P0 分级，最高只能定 P2
- **来源**：对比CN-w19-02 P0 + 对比CN-w11-02
- **集成**：AI Commerce Hub 商机分级引擎

## 裁决层

### cons-010 后悔率追踪（P1 · 2608.17644 + 2608.18058）

- **问题**：满意度会被推荐结果塑造，不能反映决策质量；后悔率（事后是否想撤销）是更诚实的指标
- **方案**：对已自动执行的决策按周记录"事后是否想撤销"，替代满意度作为主指标；后悔率上升即触发决策链路回查
- **来源**：对比CN-w19-02 P2 + 对比CN-w16-01
- **集成**：商机日报V3 周报 + delegation-asymmetry-engine deleg-008

### cons-011 偏好漂移月检（P1 · 2608.17644 + 2608.18058）

- **问题**：偏好不是稳定内在对象，可能被问法、被推荐结果、被记忆级联反向改写——契约锚不住偏好漂移
- **方案**：每月对比"声明的偏好"与"实际被推荐/成交的分布"，持续单向偏离即判定漂移，重置显式契约
- **来源**：对比CN-w18-05 P0 + 对比CN-w16-01 P1
- **集成**：delegation-asymmetry-engine 委托契约 + 异见银行立场审计

### cons-012 外置参照系（P2 · 2608.17644 + 2608.17471）

- **问题**：内部一致性不可得时，仅靠自省无法建立标尺——"内部无标尺，外部有地图"
- **方案**：任何"AI 评估 AI"产出（Skill 质量、方案优劣、偏好排序）必须指明外部参照系（人类方法集 / 历史决策库 / 基准任务集）；无参照系的自评结果标记为不可信，不进决策链
- **来源**：对比CN-w18-06 P0 + 论文CN-w04-03
- **集成**：zhengming-SkillLens + 六态状态机外置一致性关卡
