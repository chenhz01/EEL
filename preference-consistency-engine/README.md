# 偏好自洽性闸门（Preference Consistency Engine）

> **一句话主张**：LLM 当价值裁判时，"每条判断都有证据"不够——一组各有证据的判断仍可能整体不自洽；决策链路必须在集合层面加一道自洽性闸门，把"伪精确的效用函数"换成"分布 + 区间 + 人工裁决"。
>
> 主锚点：[arXiv:2608.17644](https://arxiv.org/abs/2608.17644) *LLM-Derived Preference Judgments Are Not Self-Consistent* ｜ 规格 cons-001~012（四层防线）｜ 由 5 篇对比衍生（w15-05 / w17-07 / w18-06 / w18-09 / w19-02）与论文深读提炼。

---

## 〇、与 EEL 的边界（先讲清，避免重复）

EEL 的 G2（证据指纹）回答"**这条判断有没有证据**"——纵向可信。本引擎回答"**这组判断放在一起还成不成立**"——横向自洽。论文证明两者独立：每条判断都附完整证据、问法都合理，集合仍可能无解（两两判断互相打架，无法被任何单一效用函数概括）。

| 关注点 | EEL G2（双环诊断） | 本引擎（集合级一致性） |
|---|---|---|
| 检验对象 | 单条判断 ↔ 其证据链（纵向） | 一组判断 ↔ 判断之间（横向） |
| 失效模式 | 证据断链、规范幻觉 | 传递性破坏、无差异点矛盾 |
| 放行语义 | 有证据指纹 → 可入库 | 集合通过一致性检验 → 才可进决策链路 |
| 互补关系 | 证据环 + 诊断环（D2ACCI 双环） | 第三环：一致性环（w18-09 的融合点） |

**EEL 保证"每条判断有据可查"，本引擎保证"一组判断整体可信"。缺一不可：证据完好而集合不自洽，照样是伪精确决策。**

## 一、问题：价值裁判的"自洽性盲区"

[arXiv:2608.17644](https://arxiv.org/abs/2608.17644) 系统检验了正在流行的管线——"问 LLM 这个人愿为某物付多少钱 → 拟合效用函数 → 做决策"：在航班、公寓、酒店三类场景、六个 LLM 上，同一批基数偏好判断**无法被任何单一效用函数忠实概括**——A、B 两物的支付意愿之差，不等于让此人对交换二者无差异所需的补偿金。不自洽"大且持续"，且偏好是**问法敏感的**：换个问法，答案就变。

三个结构性后果：

1. **伪精确**：用效用函数"收编"一组互相冲突的判断，是在制造虚假的一致性——输出的点估计看起来精确，实际是幻觉；
2. **误差放大**：材料中知识复利公式（价值 = 输入质量 × 裂变系数^复用次数）对输入评分极其敏感，输入的不自洽会被指数机制放大成"复噪"而非"复利"；
3. **决策链失守**：商机 P0/P1/P2 分级、UUMit 定价、付费意愿评估若直接消费 LLM 打分，等于把不可靠输入送进自动执行链路。

## 二、为什么现有方案不够

| 现有做法 | 隐含假设 | 为什么失效 |
|---|---|---|
| 逐条验证（六态状态机 status） | 条条为真 = 整体可信 | 论文证明"条条正确、整体失效"是常态——状态机对集合级质量失明 |
| 单问法评分 | 问法不影响答案 | 偏好是问法建构的，换问法答案即变 |
| 点估计输出（"值 100 元"） | 价值是稳定标量 | 不自洽大而持续，点估计掩盖度量模糊 |
| 信任 LLM 效用函数 | 判断可被单一函数概括 | 拟合出的效用函数是虚假一致性 |

## 三、引擎设计：四层防线

**问法层（暴露不自洽）**——多问法交叉评分、重述稳定性检验。
**检验层（量化不自洽）**——效用函数拟合检验、传递性检验、无差异点检验。
**闸门层（挡住不自洽）**——集合级一致性关卡、区间报价、方差超阈值标记。
**裁决层（处理不自洽）**——人工裁决回退、后悔率追踪、偏好漂移月检、外置参照系。

## 五、失败剧本：商机分级里的"伪 P0"

1. 早报抓到"抖音下调本地生活佣金"信号 → 商机引擎问 LLM"这条值多少钱"。
2. 问法 A（值多少钱）给 8/10，问法 B（省多少时间）给 4/10，问法 C（相比 X 优先级）给 6/10——**同一信号，三个档位**。
3. 若按单问法点估计：直接进 P0，当天排拍摄脚本（伪 P0）。
4. **本引擎介入**：cons-001 三问法交叉 → cons-003 拟合检验发现无单一函数概括 → cons-008 方差超阈标记"价值待定" → cons-006 集合级关卡拒绝进 P0 → cons-007 输出"区间 4~8 分，仅供参考" → cons-010 若曾自动执行过，进后悔率追踪。
5. **裁决**：cons-011 月度对比发现该信号实际成交为零 → 判"偏好被问法建构"，重置分级契约。

## 六、落地路径

- **P0（先做）**：多问法交叉评分、效用函数拟合检验、传递性检验、集合级一致性关卡、区间报价。
- **P1（再做）**：重述稳定性、无差异点检验、方差超阈值标记、商机证据类型必填、后悔率追踪、偏好漂移月检。
- **P2（后做）**：外置参照系。

## 七、与同仓库引擎的关系

- **EEL G2**：见边界表——证据环在前，一致性环在后，两环串成完整防线。
- **delegation-asymmetry-engine**：后悔率是它的主指标，本引擎为后悔率提供"偏好漂移"的测量来源——deleg-008 委托透明度条的输入之一。
- **cognitive-memory-engine**：价值评分多问法化后，中位数 + 方差一起入库，方差超阈卡片标记"价值待定"，不进入高复用推荐池（对应 cog 系列的"低稳即降权"）。

## 八、诚实的局限

1. **阈值是启发式**：方差超阈的阈值、拟合检验的残差标准，均未经验证校准，需在真实决策日志上跑对照实验。
2. **多问法增加成本**：每个价值判断 × 3 种问法，推理成本 ×3，需与决策收益权衡（对应 EEL 的"规则触发成本不为零"）。
3. **人类裁决依赖人**：不自洽集合的最终裁决需要人工，若人也不自洽（决策科学表明人类偏好同样不稳定），裁决本身需要第二参照。
4. **本文规格是论文结论的可执行表达，非忠实复现**：2608.17644 的完整统计检验细节以原文为准。
5. **模型版本时效性**：LLM 偏好自洽性可能随版本迭代改善，本引擎的检验必须随模型升级持续复测（呼应活基准思想）。
