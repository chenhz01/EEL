# 活基准引擎（Living Benchmark Engine）

> **一句话主张**：结论有时效——"当时对的结论"会随世界漂移 silently 过期。静态验证制造"知识恒常幻觉"，与静态基准制造"排名稳定幻觉"同构；修复方式也同构：让验证随时间滚动，而不是提高单次验证精度。每条沉淀知识必须标时敏性，时敏类绑定复测周期，过期自动降级。
>
> 主锚点：[arXiv:2608.17299](https://arxiv.org/abs/2608.17299) *LiveHouse-TS: An Open-world Living Benchmark* ｜ 规格 live-001~012（四层防线）｜ 由对比衍生 w18-07 与论文深读提炼。

---

## 〇、与 EEL 的边界（先讲清，避免重复）

EEL 回答"**进化有没有留痕**"。本引擎回答"**沉淀的知识现在还对不对**"——时间维度的有效性治理。两者互补：

| 关注点 | EEL | 本引擎 |
|---|---|---|
| 对象 | 进化事件的审计记录 | 知识结论的时间有效性 |
| 失效模式 | 改了没记录 | 真但已过期、复灌过期分布 |
| 放行语义 | 事件有据可查 | 常青类无限回流，时敏类绑定复测周期 |
| 与 G5（可重放闸门） | G5 管结论可复现 | 本引擎管结论可复测（复现是时点，复测是时段） |

**EEL 保证"你的结论当时有据"，本引擎保证"你的结论现在依然有据"。**

## 一、问题：知识也会"过期中毒"

[arXiv:2608.17299](https://arxiv.org/abs/2608.17299) 用活基准击穿一个被广泛忽略的假设：时间序列基础模型在静态基准上的排名，换到真实未来数据按时间顺序（prequential）持续评估后发生**剧烈重排**——静态榜领先者不一定活得好。季节波动、分布漂移、意外事件让"当时对的结论"随时间失效。评估对象必须从快照准确率升级为**连续时间有效性**。

材料中的映射：研读管线假设"回流的知识越陈越香"（间隔重复逻辑），活基准证明部分知识**越陈越毒**——漂移后复灌过期分布。AutoResearch 的输入过滤挡得住幻觉，挡不住"真但已过期"。**静态验证制造的"知识恒常幻觉"，与静态基准制造的"排名稳定幻觉"同构。**

## 二、为什么现有方案不够

| 现有做法 | 隐含假设 | 为什么失效 |
|---|---|---|
| 入库即定格 | 结论长期有效 | 分布漂移让当时对的结论随时间失效 |
| 间隔重复无差别回流 | 所有知识越陈越香 | 时敏知识越陈越毒，复灌过期分布 |
| 一次性发布 | 验证发生在消化那一刻 | 幻觉治理在时点，过期治理在时段 |
| 单次验证精度 | 精度高=可靠 | 与提高单次验证精度同构的陷阱——应让验证随时间滚动 |

## 三、引擎设计：四层防线

**标注层（分清时敏）**——时敏性三分类（常青/时敏/过期）、失效日期字段。
**复测层（滚动验证）**——prequential 复测例程、结论复测队列、静态结论占比监控。
**降级层（自动处置）**——过期降级机制、复测不通过自动降级、引用方通知。
**调度层（分流回流）**——回流分时敏分流、常青类间隔重复、时敏类绑定复测周期。

## 五、失败剧本：一条"真但已过期"的研读结论

1. 三月研读《某平台佣金政策分析》→ 结论"本地生活佣金 5%"入库 → 标记 published（当时为真）。
2. 六月平台调佣 → 该结论在知识库里依然是"5%"。
3. 商机引擎检索到该结论 → 当作当前事实用于 P0 分级 → **决策建立在一个已过期的分布上**。
4. **本引擎介入**：live-001 该结论标"时敏"→ live-002 绑定失效日期 → live-006 到达复测周期进入复测队列 → live-003 prequential 复测发现与最新真实数据不符 → live-007 自动降级为"历史语境（2026-03）"→ live-008 通知所有引用该结论的流程（商机引擎 P0 分级降权）。
5. **调度**：live-009 后续同类政策分析走时敏通道，live-010 常青类（如"间隔重复原理"）继续无限回流。

## 六、落地路径

- **P0（先做）**：时敏性三分类、prequential 复测例程、过期降级机制、回流分时敏分流。
- **P1（再做）**：失效日期字段、结论复测队列、复测不通过自动降级、引用方通知、常青类间隔重复、时敏类绑定复测周期。
- **P2（后做）**：静态结论占比监控、过期清单。

## 七、与同仓库引擎的关系

- **EEL G5（可重放结论闸门）**：G5 管"结论可复现才入图谱"（时点），本引擎管"结论可复测才保持可信"（时段）——G5 之后接本引擎。
- **cognitive-memory-engine**：cog-001 间隔重复回流调度器按遗忘曲线复习；本引擎给回流队列加时敏分流——常青走间隔重复，时敏走活基准复测。
- **verification-protocol-engine**：verf 的"噪声地板"管空间维度（换种子/换批次），本引擎的 prequential 管时间维度（换时段）——两轴合成完整的有效性评估。

## 八、诚实的局限

1. **复测成本真实存在**：prequential 复测需要持续接入最新数据，数据源中断即复测失效。
2. **时敏分类本身会过期**：一条知识从常青变时敏、从时敏变过期，分类需要周期重审（元层面同样需要活基准）。
3. **降级可能误伤**：结论"过期"可能是数据源噪音而非真实漂移，需配漂移确认机制。
4. **本文规格是论文结论的可执行表达，非忠实复现**：LiveHouse-TS 的完整基准协议以原文为准。
5. **复测频率是启发式**：绑定多久复测一次需按领域漂移速度校准。
