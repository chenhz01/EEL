# 创新度量引擎（Innovation Metric Engine）

> **一句话主张**：AI 生成内容的"新"是幻觉——名字是新起的、描述是新写的，方法论骨架可能只是对已有产物的精确复刻。任何声称"新"的产出（新 Skill、新裂变、新设计）必须附模块级差异报告：复用 / 重组 / 新组合，三选一，讲不清差异就不许叫新。
>
> 主锚点：[arXiv:2608.17471](https://arxiv.org/abs/2608.17471) *When AI Designs AI: Innovation or Imitation?* ｜ 规格 innv-001~012（四层防线）｜ 由对比衍生 w20-03 / w15-09 与论文深读提炼。

## 〇、与 EEL 的边界（先讲清，避免重复）

EEL 回答"**进化有没有留痕**"。本引擎回答"**所谓的新到底新不新**"——创新性的量化审计。两者互补：

| 关注点 | EEL | 本引擎 |
|---|---|---|
| 对象 | 进化事件的审计记录 | 新产出的新颖度判定 |
| 失效模式 | 改了没记录 | 换壳刷数量、重组当创新 |
| 放行语义 | 事件有据可查 | 声称"新"必须附差异报告，纯复用不挂新节点 |
| 与 G5（可重放闸门） | G5 管结论可复现 | 本引擎管产出可差异化 |

**EEL 保证"你的每一步都有记录"，本引擎保证"你的每一次'创新'都经得起比对"。**

## 一、问题：96.8% 的"创新"只是重组

[arXiv:2608.17471](https://arxiv.org/abs/2608.17471) 从人类方法推导"任务专属算法设计空间"，把人类与 Agent 设计的方法都映射进去做模块级量化，结论冷峻：

- **96.8% 的 Agent 设计落在人类推导的设计空间内**，大量只是重组人类既有算法选择；
- **近一半精确匹配某个已有人类算法设计**——即"精确复刻"；
- 10/72 配置偶尔达到或超越人类 SOTA，但跨任务、跨 Agent 都不可靠泛化——**偶发的真超车确实存在，只是不可靠**。

材料中的两处映射：(1) Skill 目录按数量增长叙事自我扩张，无差异度量的孵化产线产出的"新 Skill"大概率是换壳；(2) 母题子题树用"树越深=裂变越充分"衡量资产厚度，但子题数量不等于创新数量——**深度的大部分是重组膨胀**。

## 二、为什么现有方案不够

| 现有做法 | 隐含假设 | 为什么失效 |
|---|---|---|
| 数量增长即进步 | 新产出=新能力 | 无差异度量的产线，产出大概率是人类空间的重组 |
| 树越深=资产越厚 | 子题多=创新多 | 可能是同一组模块反复重组，换个角度讲同一件事 |
| 名字新=内容新 | 命名即创新 | 可得性偏差+惊叹偏差：记住 10 次超车，忽略 96.8% 的模仿 |
| 占比当活性 | 新组合占比高=活跃 | 占比永远会被重组稀释，应看新组合绝对数 |

## 三、引擎设计：四层防线

**度量层（拆出模块）**——四模块拆解（触发/流程/输出/依赖）、设计空间映射。
**判定层（定出类型）**——差异类型三选一（复用/重组/新组合）、重合度阈值、换壳判定。
**闸门层（挡住虚胖）**——差异报告强制、纯复用不挂新节点、孵化出口门槛。
**活性层（看清趋势）**——双指标聚合（总数+新组合绝对数）、创新奖励阈值、创新停滞预警。

## 五、失败剧本：Skill 目录的"换壳膨胀"

1. 进化引擎每周孵化 3 个"新 Skill"，目录从 26 涨到 60，报告很漂亮。
2. 实际审计：60 个里 38 个是已有 Skill 的变体（换个触发词/输出格式），12 个是精确复刻——**真新只有 10 个**。
3. **本引擎介入**：innv-001 四模块拆解 → innv-003 差异类型标注 → innv-005 换壳判定（重合度>80% 判换壳）→ innv-006 无差异报告不登记 → innv-007 纯复用产出不挂新节点 → innv-012 存量体检：26 个 Skill 两两重合度矩阵，识别可合并变体。
4. **裁决**：innv-011 新组合绝对数连续 3 周停滞 → 判定进入重组内卷 → innv-010 对模块差异>30% 的真创新加权奖励，引导探索设计空间之外。

## 六、落地路径

- **P0（先做）**：四模块拆解、差异类型三选一、换壳判定、差异报告强制、存量体检。
- **P1（再做）**：设计空间映射、重合度阈值、纯复用不挂新节点、孵化出口门槛、双指标聚合、创新停滞预警。
- **P2（后做）**：创新奖励阈值。

## 七、与同仓库引擎的关系

- **EEL G3（自进化审计账本）**：G3 要求策略变更记录动机+数据+回测；本引擎要求新 Skill 记录差异报告——同为"变更必须带元数据"家族。
- **preference-consistency-engine**：cons-012 外置参照系与本引擎设计空间映射同构——都要求"外部地图"而非内部自评。
- **verification-protocol-engine**：verf-012"协议 vs 裸 Skill 成功率"需要先分清哪些 Skill 是真新——本引擎提供分层。

## 八、诚实的局限

1. **设计空间映射依赖人类方法集完备性**：若人类方法集本身不全，Agent 跳出空间的设计会被误判为重组。
2. **四模块拆解粒度主观**：拆到什么粒度影响重合度判定，需先定拆解规范并测评分者一致性。
3. **"真创新"低频**：论文显示真超车偶发且不可靠——奖励真新不能只奖励频率，还要跟踪其后验绩效。
4. **本文规格是论文结论的可执行表达，非忠实复现**：2608.17471 的完整模块量化方法以原文为准。
5. **差异报告可被虚填**：需抽样核验而非只信自报（与 verf 引擎的抽样核验共用同一机制）。
