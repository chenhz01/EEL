# 版本化工作区引擎

> **一句话主张**：知识工作智能体最大的风险不是想错，而是**就地覆盖**——把工作区做成「暂存区 + 提交 + 回滚」的版本化结构，能把不可逆错误变成可逆错误，这比提升模型能力便宜得多。
>
> 主锚点：[arXiv:2608.18050](https://arxiv.org/abs/2608.18050) *StagedWorkspace: A Versioned Workspace for Knowledge-Work Agents* ｜ 规格 vers-001~012（四层机制）｜ 由论文深读、四位顾问脑暴与对比衍生提炼。

---

## 一、问题：知识工作没有编译器

与写代码不同，知识工作缺少编译器和测试：错误不会立即报错，往往在很多步之后才被发现，而此时智能体已经在原文件上覆盖了几十次。论文的关键实验结论有三：

1. **短任务上就地编辑与版本化几乎无差别，差距在长任务与多智能体协作时爆发**——小规模实验会严重低估风险。
2. 版本化的收益主要来自**错误可逆**，而非错误更少。
3. 最有效的单点措施是「**写操作默认进暂存区**」，其余机制都是在此之上的增益。

把工作区看成外部记忆，会发现它与人类记忆同构：覆盖式重编码会污染原始记忆（第 20 次改写后没人知道第 1 版为何这么说）；间隔重复的前提是可比对——若标准答案本身被每次回答改写，重复就退化为自我强化。

## 二、为什么现有方案不够

| 现有做法 | 隐含假设 | 为什么失效 |
|---|---|---|
| 定期手动备份 | 备份点=安全 | 无依据元数据，恢复后不知道「该回到哪个版本、为什么」 |
| git 式版本控制原样搬 | Agent 会像人一样 commit | Agent 不写提交说明；无可见性隔离，「看到了就想改」 |
| 全量重做 | 重来最省 | 长程任务全量重做代价高昂且打断上下文连续性，断点续作才是主路径 |
| 保留一切版本=更安全 | 快照越多越好 | 被污染的内容保留=给攻击者弹药库，提交元数据反而帮攻击者定位高可信节点（联动极化引擎 2608.17665） |

## 三、引擎设计：四层机制

**暂存层（写前暂存）**——写操作默认进暂存区、覆盖写先出 diff、费曼式变更说明（讲不清不合并）。
**提交层（原子提交）**——提交带依据元数据、记忆追加+版本链、可寻址快照+指纹存证。
**恢复层（可逆兜底）**——任意提交点回滚与分叉、断点续作双层恢复、不可逆损坏率指标。
**协作层（并行隔离）**——多子 AI 并行分片工作区、可见性隔离、决策版本化复习。

## 五、运行推演：30 子 AI 并行扩建知识库

1. **暂存**：子 AI-7 要改写 Capsule 节点 → 先落 `.staged` 版本，生成 diff 与费曼说明「把 X 从 v3 提到 v4，因为论文 w01-04 支持该结论，影响下游 3 个引用节点」。讲不清的说明不允许进入审批。
2. **提交**：说明与依据通过校验 → 原子提交进主区，生成可寻址快照 + 指纹存证，元数据记录「谁写的 / 依据什么 / 替代 v3」。
3. **恢复**：3 天后发现 v4 依据有误 → 回滚到 v3 提交点；另一分支的 v4b 继续推进，择优合并，而不是在同一份文件上反复涂改。
4. **协作**：30 个子 AI 各自写 `w01/` 前缀目录，禁止跨前缀写入；各自只见所需切片，避免「看到了就想改」。
5. **复习**：战略决策快照按 1/3/7 天回看，留存「为什么这么改」的决策逻辑，复盘不再归罪于人。

## 六、落地路径

- **P0（先做）**：写默认进暂存区、覆盖写先出 diff、记忆追加+版本链、任意提交点回滚与分叉。
- **P1（再做）**：提交带依据元数据、可寻址快照指纹、并行分片、可见性隔离、断点续作、决策版本化复习。
- **P2（后做）**：不可逆损坏率指标、费曼式变更说明的教学化沉淀。

## 七、与同仓库文章的关系

- **EEL**：EEL 记录「改了什么」（账本），本引擎提供「改的落盘结构」（仓库管理）——EEL 的事件是追加式，本引擎的快照链是这些事件的可寻址载体。
- **delegation-asymmetry-engine**：委托审计台账要求可审计轨迹，版本化工作区是轨迹的物理载体。
- **capability-collapse-defense**：塌缩防线决定「何时回滚」，本引擎提供「怎么回滚」——轮级回滚与恢复成本台账都依赖版本化快照。
- **polarization-depolarization-engine**：写入立场偏移检测（污染不入库）与来源配额（污染难复现）是本引擎快照策略的必要补充，防止「保留一切=安全」的误区。

## 八、诚实的局限

1. 版本化不减少错误，只让错误可逆——错误更少仍需其他机制（如认知记忆引擎的间隔重复）。
2. 快照与元数据本身会膨胀，需要降权/归档生命周期策略。
3. 断点续作依赖任务可序列化，并非所有任务适用。
4. 本文规格是论文结论的可执行表达，非忠实复现；精确实验数值以原文为准。
5. 可见性隔离若过度收紧会破坏跨任务复用，需要与知识图谱的共享需求做平衡。
