# 验证协议引擎（Verification Protocol Engine）

> **一句话主张**：单次成功观测 ≠ 通过检验的估计量。任何"先跑通再复制"的动作——账号矩阵、Skill 复制、商机验证——都缺一份显式的统计验收协议：检验什么、多大样本、什么置信水平下算通过；先测噪声地板，再看真实变化。
>
> 主锚点：[arXiv:2608.17744](https://arxiv.org/abs/2608.17744)（噪声地板）+ [arXiv:2608.17724](https://arxiv.org/abs/2608.17724)（VERaiPHY 统计验证标准）｜ 规格 verf-001~012（四层防线）｜ 由对比衍生 w11-02 / w11-03 与论文深读提炼。

---

## 〇、与 EEL 的边界（先讲清，避免重复）

EEL 回答"**进化有没有留痕**"——审计账本。本引擎回答"**宣称的成功是不是真的**"——验证协议。两者互补：

| 关注点 | EEL | 本引擎 |
|---|---|---|
| 对象 | 进化事件的审计记录 | 成效宣称的统计验收 |
| 失效模式 | 改了没记录、假提交 | 单点成功当真理、噪声当信号 |
| 放行语义 | 事件有据可查 | 宣称达到预设置信线才算"验证过" |
| 与 G5（可重放结论闸门） | G5 管"结论可复现才入图谱" | 本引擎管"复现要多少样本、什么判据" |

**EEL 保证"你做的都记下来了"，本引擎保证"你说的成功经得起统计检验"。**

## 一、问题：把一次观测当成通过检验

两个来源各自击中一个盲区：

1. **[2608.17744]（噪声地板）**：把前沿 MoE 模型微调为用低资源语言推理，准确率基准几乎没动——**且在该规模下基准本身就是噪声：仅换随机种子分数就波动 7.7 个点，超过所有数据与配方效应**。真实变化发生在准确率看不见的维度（推理语言、格式遵从）。教训：小样本单一指标的信噪比可能为负，首单可能只是种子运气。
2. **[2608.17724]（VERaiPHY）**：机器学习给基础物理带来收益，但**统计验证、不确定性量化与鲁棒性评估被系统性忽视**；该系列为物理 AI 的开发、评估与部署建立统计标准。教训：验证必须有预设的统计协议——检验什么、多大样本、什么置信水平下算通过。

材料中的映射："带牌带货账号矩阵"把单号 7 天 GMV 破万当作已验证闭环，直接 ×N 复制；"50 件事"每件事挂验收标准却只挂结果指标（订单数）。**单点 GMV 破万是一次成功观测，不是一个通过检验的估计量。**

## 二、为什么现有方案不够

| 现有做法 | 隐含假设 | 为什么失效 |
|---|---|---|
| 单号 7 天 GMV 破万即验证 | 一次成功 = 能力成立 | 首单可能是种子运气，波动 > 真实效应 |
| 只盯结果指标（订单数/收益） | 指标上升 = 变好 | 真实变化可能藏在准确率看不见的维度 |
| 复制无配额 | 已验证即可无限复制 | 未审计的模型被部署到 N 个账号，风险×N |
| 全量日巡检 | 每个站点都值得天天查 | 算力摊平在低信息站点上 |

## 三、引擎设计：四层防线

**协议层（写清判据）**——验证协议五字段、验收双指标（结果指标 + 过程指标）、置信线与样本量预设。
**噪声层（先测地板）**——噪声地板检测、种子稳定性检查、控制组对照。
**验收层（执行检验）**——验证状态停留期、复现性门槛、鲁棒性指标入协议。
**治理层（控制复制）**——复制配额分级、差分归因、季度成功率统计。

## 五、失败剧本：矩阵复制的"种子运气"

1. 单号 A 用钩子模板，7 天 GMV 破万 → 判定"已验证闭环"。
2. 直接复制 10 个新号（复制无协议）。
3. 10 个号里 8 个数据惨淡——首单的成功部分是种子运气（噪声），且没测噪声地板，把波动当信号。
4. **本引擎介入**：verf-001 要求验证协议五字段（指标/周期/样本/置信线/通过线）→ verf-004 测该品类的噪声地板（前 10 单波动区间）→ 发现 7 天 GMV 波动区间覆盖"破万"，判定**不可判读** → verf-010 复制配额按验证等级分级（未验证 Skill 只能单号试运行）→ verf-011 用同期未改动对照号差分后再下结论。
5. **裁决**：verf-012 季度统计"带协议 Skill vs 裸 Skill"复制成功率差，用数据说服持续付验证成本。

## 六、落地路径

- **P0（先做）**：验证协议五字段、验收双指标、噪声地板检测、验证状态停留期、复制配额分级。
- **P1（再做）**：置信线与样本量预设、种子稳定性、复现性门槛、鲁棒性指标、差分归因、协议成功率统计。
- **P2（后做）**：控制组对照。

## 七、与同仓库引擎的关系

- **EEL G5（可重放结论闸门）**：G5 管"不可复现即降级"，本引擎提供"复现到什么程度算通过"的判据——G5 是闸门，本引擎是判据源。
- **preference-consistency-engine**：商机分级的"付费意愿"证据类型（真实成交/LLM 推演）由本引擎的"证据来源标注"支撑。
- **capability-collapse-defense**：clps-002 任务顺序方差基线与本引擎的种子稳定性检查同构——都测"换一种排列结果还稳不稳"。

## 八、诚实的局限

1. **协议本身可被敷衍**：五字段可以填假值；需配抽样核验，而非只信自报。
2. **噪声地板测量需要历史数据**：新业务线无前 10 单历史时，噪声地板只能先估后用。
3. **控制组有成本**：同期跑未改动对照业务线占用资源，P2 优先级反映此权衡。
4. **本文规格是论文结论的可执行表达，非忠实复现**：VERaiPHY 系列的完整统计方法论以原文为准。
5. **统计显著性 ≠ 业务显著性**：通过统计检验只说明"不是噪声"，不代表"值得规模化"——决策层仍需业务判断。
