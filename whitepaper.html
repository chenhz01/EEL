EEL — Evolution Evidence Ledger

A Zero-Dependency Audit Layer for Self-Improving AI Agents

1. The Problem: Self-Improvement Without a Paper Trail

A system that modifies its own rules, memory, and policy is among the most consequential artifacts of this decade. It is not most dangerous when it makes a mistake — it is most dangerous when it makes a mistake and nobody can tell what changed or why.

The 2026 wave of self-improving agent research makes this concrete:

  • arXiv:2608.18066 shows self-improving agents do not monotonically improve — capability is a function of algorithm × task order × specification, and changing task order alone can crater capability.
  • Yet the current generation rewrites its own prompts, policies, and memory with no immutable record of what changed and why.

Fear of runaway is speculation. The absence of an audit trail is a fact. EEL takes the audit trail as the primary object of engineering.

2. What EEL Is

EEL (Evolution Evidence Ledger) is a minimal, zero-dependency, append-only audit layer for self-improving agents. Three layers:

  • Six Guardrails (G1–G6) — each converts an arXiv paper conclusion into an enforceable rejection, not a reminder.
  • Hash-Chain Ledger — every evolutionary event is written append-only; tampering is cryptographically exposed.
  • Ten Governance Engines / 160 executable specs — paper conclusions turned into runnable specifications.

Design principle: Evolution is evidence. Evidence is immutable.

4. The Hash-Chain Protocol

Each event is an Event Block linked by SHA-256:

hash(block_n) = SHA256( prev_hash(block_n) ∥ canonical_json(payload_n) )
canonical_json = keys sorted lexicographically, no whitespace, UTF-8
  • Genesis block: index=0, prev_hash="sha256:GENESIS".
  • Append-only: index strictly +1; no deletion, no rewrite.
  • Tamper detection: editing any intermediate block breaks every subsequent prev_hash → whole-chain verification fails.
  • Replay: any verifier independently recomputes every hash without trusting any node.

5. The Value Kernel (数学化"美好方向")

"As long as you define an accurate, beautiful direction, you can converge value orientation." EEL operationalizes this:

  • Three-layer ethical constitution: L0 (immutable red lines) → L1 (domain norms) → L2 (individual preference).
  • Value is a vector: score = mean(cosine_sim(action_vec, norm_vec_i)).
  • Hard constraints dominate soft goals: maximize U(a) subject to Val(a) ≥ VAL_MIN and Risk(a) ≤ RISK_MAX.
  • Drift detection: auto-rollback on sustained offset.

Honest limitation: value vectorization depends on embedding quality; L0 hard rules are the backstop; drift thresholds need calibration.

6. Distributed Consensus (PBFT + VRF)

  • PBFT for small fixed committees (fault tolerance f < n/3).
  • VRF for leader election in open committees.
  • Unconfirmed consensus → block stays PENDING, never silently admitted.

7. Recursive Improvement Sandbox

Self-improvement runs inside a recursive sandbox: simulated rollout before commit, locked "break-glass" passwords for irreversible actions, full event capture back into the ledger.

10. Why It Matters (Asset Thesis)

EEL is the only system unifying four previously separate concerns into a single immutable ledger:

  • Trust (cryptographic tamper-evidence)
  • Transparency (every change has a why)
  • Value alignment (mathematical "good direction")
  • Evolution governance (six laws + consensus)

An audit system must first survive being audited itself — which is why we publish our negative result.
