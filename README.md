## 一句话定位

> **AI 会进化，但"它真的变强了吗"从来无法被证伪——EEL 用不可篡改的进化账本，把每一次能力唤醒、每一分外溢价值变成可审计、可追溯的证据链。**

## 问题：自进化 AI 的三个静默失败

给 AI 装上记忆、技能库和自我改进循环之后，你会遇到三种没人注意的失败：

1. **自证陷阱**：系统用自己的产出证明自己的价值（循环论证），"看起来很忙"≠产生了外溢价值
2. **进化断点**：某个能力被唤醒过一次，之后再也没有被任何真实任务用过——装了 = 用了是最大的幻觉
3. **无审计链**：能力接入、验收、复用之间没有证据链，出问题时无法回答"当时谁验收的、依据是什么"

EEL（Evolution Evidence Ledger）针对这三个失败给出账本式解法。

## 方案：三层账本架构

```
┌──────────────────────────────────────────────┐
│ KPI 层   外溢价值度量：入链证据必须回答          │
│          「被谁用了」，答不出记 ORPHAN 不计分     │
├──────────────────────────────────────────────┤
│ 验收层   「学·超·破·用」闭环第⑤步 = 真实演示：   │
│          端到端跑通并产生可验证产物才算入链        │
├──────────────────────────────────────────────┤
│ 账本层   只追加（append-only）+ 哈希锚定：        │
│          每条进化事件可追溯、防篡改、可回滚        │
└──────────────────────────────────────────────┘
```

核心设计原则：

- **证据三问**：每条入链记录必须回答——谁验收的？跑通了什么端到端产物？被哪个后续任务真实复用？
- **ORPHAN 机制**：唤醒了但从未被复用的能力，标记为孤儿，不进 KPI，倒逼"装了 ≠ 用了"的诚实核算
- **诚实基线**：账本上线第一件事是记录系统的真实复用率（哪怕为零）——先承认现状，才能度量进化

## 深度示例：一条真实的入链记录（脱敏）

```json
{
  "event": "capability_awakened",
  "capability": "memory-integrity-checker",
  "acceptance": {
    "method": "end_to_end_demo",
    "artifact": "boot-check report, 9/9 checks passed",
    "witness": "human owner"
  },
  "reuse": {
    "first_real_task": "session boot, 2026-09",
    "status": "LINKED",
    "orphan": false
  }
}
```

一次"真实演示"验收 → 产生可追溯产物 → 被后续真实任务复用 → 记为 LINKED。
